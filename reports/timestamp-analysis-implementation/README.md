# 時間帯別の合成ブラウザ検証データ

このフォルダの JSON はブラウザ操作確認用の合成 fixture です。コメント本文・投稿者・ID はすべて架空で、既存 `sampleItems` の確率分布だけを利用しています。実動画のコメントを転記したものではありません。Jev やコメント取得 API は使用しません。動画埋め込みの確認には YouTube への接続が必要です。

## ファイル

| ファイル | 内容 |
| --- | --- |
| `fixture.json` | 20件、動画ID `zuQb52Up9VQ`、尺2,964秒。全角・0秒・境界・同秒/同区間重複・複数区間・未取得・空区間・動画尺外・URL/時計除外・長文を含みます。 |
| `legacy-fixture.json` | 同じ20件のv1データ。`video.durationSeconds` を省略し、旧保存データの互換性と後からの尺補完を確認できます。 |
| `unknown-fixture.json` | 3件すべて感情未取得。件数はあるが感情の線は欠損となる状態です。 |
| `extreme-legacy-fixture.json` | 尺なし2件。`9999:59:59` を含み、大量の空区間を生成せず退避表示できるか確認します。プレイヤーから尺を取得すると極端な候補は除外されます。 |

すべて `analysis.source: "sample"`、使用トークン・料金0、固定保存IDの検証データです。生成スクリプトはこのフォルダの fixture だけを書き込み、アプリの保存ストアには書き込みません。

## 読み込み手順

1. リポジトリで `npm run dev` を実行し、表示されたローカルURLを開きます。
2. アプリの「保存データを開く」から「JSONを読み込む」を選び、対象の JSON を読み込みます。読み込みだけでは保存ストアへ書き込まれません。
3. 「時間帯別」タブを開きます。分析を開始する操作は不要です。
4. 開始 `29:18`、終了 `30:12` を指定し、30/60/120秒の変更、ズーム、コメント全文、本文時刻のクリックを確認します。
5. 全体表示やフィルター変更、通常コメントタブとの往復、360px程度の狭い画面、キーボード操作を確認します。
6. 別の fixture を同じ方法で読み込み、選択・範囲・ズームのリセットと旧データ/空状態を確認します。

## 計算上の確認値

共通フィルターを解除し、`fixture.json` の尺2,964秒を使用したときの期待値です。

- 全コメント20件、有効な時間表記あり17件。動画尺以上の候補は3件です（コメント16に1件、コメント17に2件）。
- 任意範囲 `29:18 <= t < 30:12` は8件。対象ID末尾は `07, 08, 09, 10, 11, 13, 14, 15` です。
- 同範囲は好意4件（50%）、中央2件（25%）、批判1件（12.5%）、未取得1件（12.5%）です。画面で整数表示される場合、端数は丸められます。
- `30:12` のコメント12は同範囲に入りません。コメント09と13は複数の表示区間に現れても、選択範囲全体ではそれぞれ1件です。
- `2:00–3:00` は未取得1件のみ。`4:00–5:00` は0件。`5:00–6:00` は批判1件で、好意・中央は実際の0%です。
- コメント15の全文にある `0:30` は上記任意範囲外ですがクリックできます。クリックしても分析範囲や一覧が変わらないことを確認します。
- 検索 `時刻なし` は共通条件1件・時間表記あり0件。検索 `存在しない検証語` は共通条件0件。開始 `4:00`、終了 `5:00` は範囲内0件です。
- `legacy-fixture.json` では尺が補完されるまでは `49:24` と `90:00` も候補です。最後の候補時刻を含む区間までの表示と、尺未取得の注記を確認します。

## 再生成

リポジトリのルートから以下を実行します。

```sh
node --import tsx scripts/create-timestamp-fixture.ts
```

各ファイルは生成時にアプリの保存形式バリデーターで検証されます。ブラウザでの検証結果は親タスクの検証報告を参照してください。この README は未実施の操作を確認済みとは扱いません。
